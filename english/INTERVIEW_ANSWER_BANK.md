# Interview Answer Bank

Keep bullet cues here, not memorized paragraphs. Leave personal facts blank
until you can verify them. Use [TODAY](../TODAY.md) for daily results; update
this bank only for an answer you want to revisit. Duplicate a template when useful.
Practice with the [frameworks](./README.md#explanation-frameworks), then put cues away.

## Tell me about yourself

Use facts from your actual role and projects. Select the strongest few points
for the time available and retell them naturally each time.

- Current role / relevant experience:
- Strongest technologies:
- Type of systems/features worked on:
- One strength:
- Target role:

### 60-second version

- Current role / relevant experience:
- Strongest technologies:
- Type of systems/features worked on:
- One example of my contribution:
- One strength with evidence:
- Target role / why it fits:

### 90-second version

- Current role / relevant experience:
- Strongest technologies:
- Type of systems/features worked on:
- Relevant previous experience, if any:
- One contribution / verified result:
- One strength / lesson:
- Target role / motivation:

The longer versions add depth; they need not list every skill or job.

## Project explanation

### Project entry

- Project / neutral name:
- My role / personal contribution:
- Existing project-notes link, if any:
- 30-second summary: purpose → my contribution → result:
- 2-minute explanation: context → problem → decision → implementation → result:
- 5-minute deep dive: investigation → architecture/request flow → alternatives → failure/scaling → learning:
- Last speaking weakness:

Use short bullets for each depth. Build from the [project guide](../10-Projects.md).
Describe qualitative results honestly if there is no verified measurement.
Keep company/customer names, sensitive code, logs, and confidential details out.

Follow-ups to practice; add cues only when verified:

- Why this architecture?
- Why this database?
- How does authentication work?
- What are the security risks?
- How does deployment work?
- What was the biggest issue, and how did you investigate it?
- What would you redesign?
- What happens at 10x traffic?
- What did **you** personally implement or decide?
